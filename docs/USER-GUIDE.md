# Welcome to BiForge

This guide explains how to use **all three BiForge modes**: **Simple**, **Expert**, and **Project**. You do not need to know anything about artificial intelligence to begin.

## 1. Start here {#start}

1.  Open BiForge in your web browser.
2.  On the start screen, choose the mode that best matches what you want to do. If you are unsure, begin with **Simple chat**.
3.  Type your request in ordinary language. You do not need special commands or technical vocabulary.
4.  Press **Send** (or the equivalent action shown on the screen) and wait for the response.
5.  Read the response. If it is unclear, incomplete, or based on a wrong assumption, say so and explain what needs to change.

You can ask follow-up questions. You do not have to get the wording perfect on your first try. For example, you can say: *“Please explain that in simpler English,” “Give me an example,” “You misunderstood the second point,”* or *“Ask me one question at a time.”*

## 2. How to work with an AI assistant {#basics}

### Give enough context

A useful request usually says what you want, why you want it, and any important limits. Compare these examples:

<div class="example">

**Too vague:** “Help me with a website.”

**More useful:** “I want a small website for a local gardening club. Visitors should be able to read announcements and send a contact message. I have no coding experience. Please explain the simplest approach and its likely costs.”

</div>

### Work in small steps

For a large task, ask BiForge to start with an outline, then improve one part at a time. You can ask it to stop after each step so you can review the result.

### Correct mistakes directly

If a response is wrong, do not assume the assistant will notice by itself. Point to the exact sentence or claim and provide the correction or the missing information.

### Ask for uncertainty to be explained

Ask which statements are known, which are assumptions, and what needs checking. A confident-sounding answer is not automatically a correct answer.

### Know what “Send” does

Sending a message asks the assistant to process it. It does not mean you have approved the answer, accepted a project change, published a website, or authorised a real-world action.

## 3. Choose the right mode {#modes}

| Mode                  | Use it when…                                                                                                                               | How it feels                                                                  |
|-----------------------|--------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------|
| **Simple chat**       | You have a question, need an explanation, want to draft text, or need practical help.                                                      | Like a normal conversation. No required sequence of stages.                   |
| **Expert method**     | You face an important decision and want to examine options, challenge assumptions, test ideas, and record what you learn.                  | A guided, step-by-step decision process. You move forward when you are ready. |
| **Project workspace** | You want to define a project, organise requirements and risks, create a plan, track approvals and tasks, or prepare a source-code package. | A separate workspace with project records and explicit human confirmations.   |

Use the **Mode** control in the top bar to switch between available modes. Choose **Back to mode selection** to return to the start screen. If Project is shown as unavailable, this BiForge installation has not enabled it; this is not a problem with your browser.

## 4. Simple mode: step by step {#simple}

### 4.1 Start a conversation

1.  Choose **Simple chat**.
2.  If you see the empty start screen, select **Start conversation**.
3.  Type one clear request into the message box.
4.  Press **Send**.
5.  Read the answer and continue the conversation as needed.

### 4.2 Improve the answer

Use follow-up messages to narrow or correct the response. Examples:

- “Keep the answer under 200 words.”
- “Assume I am a complete beginner.”
- “Separate confirmed facts from assumptions.”
- “Give me three alternatives and explain the trade-offs without choosing for me.”
- “Please revise the previous answer using this correction: …”

### 4.3 Start a fresh conversation

Choose **New** in the top bar. This starts a new dialogue rather than continuing the current thread. If you need the earlier conversation later, check **History** or export a copy first.

### 4.4 Use Simple mode for everyday work

Simple mode is a good place to ask for explanations, brainstorm ideas, translate or improve text, prepare a checklist, compare options, or get help understanding a document. For high-impact choices, ask for risks and uncertainties and verify important facts independently.

## 5. Expert mode: the decision method {#expert}

Expert mode is designed for decisions that deserve more care than a quick chat. It guides you through five broad loops: **Understand** (make the situation clear), **Expand** (explore options), **Attack** (stress-test assumptions), **Verify** (test ideas and evidence), and **Learn** (record the decision, plan, and lessons). The exact screen may use labels such as **Your story**, **Clarify**, **Options**, **Stress-test**, **Test ideas**, **Decide**, **Plan**, and **Learn**.

<div class="callout">

**Important:** Expert mode does not make the decision for you. The assistant helps structure the thinking; you supply your values and constraints, review the evidence, and own the final choice.

</div>

### 5.1 Describe the decision

1.  Choose **Expert method** from the Mode menu.
2.  Describe the situation in your own words. Say what decision you face and what makes it difficult.
3.  Include a deadline, budget, people affected, or non-negotiable constraints if they matter.
4.  Read the resulting summary. Correct it if it changes your meaning or leaves out something important.

### 5.2 Understand and clarify

The assistant helps separate facts, unknowns, assumptions, goals, and constraints. Answer questions when you can. If you do not know an answer, say “I don’t know” rather than guessing. Check that the assistant’s description is fair and neutral before relying on it.

### 5.3 Explore options

Review the possible paths. Add options the assistant missed, remove unrealistic options, and explain practical limits. You do not have to accept every suggestion just because it appears on screen.

### 5.4 Stress-test the options

Look for objections, failure scenarios, hidden costs, and assumptions that could be wrong. Consider what might make each option fail. The purpose is not to be negative; it is to discover problems while there is still time to respond.

### 5.5 Test ideas and evidence

Where appropriate, define what evidence would support or weaken an idea. Ask what can be checked, what result would count as success, and what would change your mind. Do not treat an untested prediction as a fact.

### 5.6 Decide

Review the trade-offs and record your own decision, including the reason if useful. The assistant may help make the wording clearer, but it must not substitute its preferences for yours.

### 5.7 Create and review the plan

Read the proposed work plan. Edit it until the actions, owners, timing, and conditions are realistic. Export it if you need to share or store it elsewhere.

### 5.8 Learn from the outcome

When you have new evidence or the result of your decision, record what happened and what differed from expectations. You can start another cycle if the situation has changed or a new decision is needed.

### 5.9 Move through the stages

- Use the Expert stage navigation to revisit earlier stages when available.
- The method does not automatically move forward just because you chat. Complete or review the current stage and use the stage controls when you are ready.
- The open conversation area remains available for questions and clarifications during the process.
- If you are unsure what a stage asks for, ask BiForge to explain the task in plain English before proceeding.

### 5.10 Save or remove a decision dialogue

Use the top-bar export options to save a copy. Expert mode also provides a **Decision brief** in **More** when enough information exists. Use **Delete dialogue** only when you really want to remove that dialogue from the local workspace.

## 6. Project mode: build and manage a project {#project}

Project mode is a separate workspace. It may require you to sign in with the application password configured by the person who runs this BiForge installation. If you do not have access, ask that administrator. Project mode can be disabled on some installations.

### 6.1 Sign in

1.  Open **Project workspace** from the Mode menu.
2.  If prompted, enter the application password supplied by the administrator and choose **Sign in**.
3.  Never send that password to the AI in a chat message.

### 6.2 Choose a project-building path

When no project is selected, BiForge offers two paths:

- **Simple words** — recommended for beginners. Describe the idea, answer a few guided questions, review the summary, and ask BiForge to create the project and prepare a source ZIP if the server supports it.
- **Professional** — for people who want more direct control. Enter a project name and optional goal, create the project, then work with the description, analysis, plans, tasks, and delivery tools.

### 6.3 Beginner path: Simple words

1.  **What do you want to build?** Describe the idea in everyday language. Include the main purpose and what a user should be able to do. You need at least a short description before Next becomes available.
2.  **Choose the product type.** Select the closest match from the choices shown. If none is perfect, choose the nearest one and clarify the difference in your idea.
3.  **Answer the practical setup questions.** Choose whether people need to sign in, whether the app needs to store data in a database, and the interface language (English, Russian, or another/mixed language). If you are unsure, choose “Not sure” rather than guessing. Add optional constraints such as “must be free to run,” “must work on a phone,” or “no paid APIs.”
4.  **Choose a technical shape.** If you do not understand the options, leave **Choose for me** selected. You can change this later with more knowledge.
5.  **Review the summary.** Check that the generated goal, inputs and outputs, and constraints describe what you actually want.
6.  Select **Create project & build ZIP**. Wait for the result. Do not close the page while it is working.
7.  If a source ZIP is produced, choose **Download source ZIP** and save it somewhere you can find again. Read the deployment instructions displayed below the download link.
8.  Use the project list and workspace for further analysis or professional tools when needed.

A ZIP file is a package of files, not a live website. Creating or downloading it does **not** publish it to the internet, upload it to GitHub, or deploy it to a hosting provider.

### 6.4 Professional path: create a project

1.  Choose **Professional**.
2.  Enter a short, recognisable project name. This field is required.
3.  Optionally enter the main goal. Be specific about the outcome you want.
4.  Choose **Create project**.
5.  Select the project in the project list to open its details. Choose **All projects** to return to the list.

### 6.5 Review the project description

The project description is the shared starting point for later analysis. Review the **Goal** field. Open **Advanced parameters** to review the project type, intended users, inputs and outputs, constraints, security and data requirements, success criteria, request/token/code-run limits, how code is written, and how involved you want to be.

1.  Edit any field that is incomplete or incorrect.
2.  Choose **Save description** to save edits without confirming the description.
3.  When it accurately represents the project, choose **Confirm description**. Analysis is unavailable until the description is confirmed.
4.  If you change important requirements later, review and save the description again before relying on subsequent results.

### 6.6 Run an analysis

1.  In **What should we analyse?**, write one clear question or task. For example: “Identify the main risks and missing requirements before we build the first version.”
2.  If useful, attach project files in the Workspace files area and confirm that the assistant may read them (see the Files section below).
3.  Choose **Run analysis** and wait for completion.
4.  Read the proposed results. The assistant may suggest facts, unknowns, hypotheses, risks, requirements, and other project items.
5.  Check each suggestion. Select **Confirm** only if it is accurate enough to keep; select **Reject** if it is wrong or unsuitable. A proposed item is not accepted automatically.
6.  Record a decision made by you or your team in **Your decision**, then choose **Add decision**. This records a human decision; it is not a decision made by the model.

### 6.7 Understand the project tabs

- **Results** — review proposed facts, unknowns, hypotheses, risks, requirements, and recorded decisions. Confirm or reject proposed items here.
- **Plan** — choose **Create a simple plan** to prepare a proposed plan. Review the plan and any pending approvals. Use **Approve** only when you understand and accept the requested action; use **Reject** when you do not. A plan must be approved before its tasks can run.
- **Tasks** (shown within the Plan area) — when a task is ready, choose **Start task** to queue it. After it runs, inspect the actual output. Use **Mark as passed** only after checking the acceptance evidence and criteria. Use **Mark as failed** if the criteria were not met. BiForge asks you to enter concrete evidence; do not mark a task as passed merely to clear the status.
- **Code package** — review code-generation or delivery hand-off information when available. Download the resulting package if offered, inspect it, and follow the manual instructions. Capabilities depend on the server configuration.
- **Files** — open saved project artifacts and versions. If Google Drive is configured, you can explicitly save an artifact to Drive.
- **Advanced** — exposes raw project JSON. This is for people who understand the data format. Incorrect JSON can damage project state; beginners should leave it alone.

### 6.8 Create a program or source package

If the **Create a program** area is available, describe the program you want and request a build. Wait for the result. If a downloadable ZIP is offered, download it and inspect its contents. If no ZIP is produced, read the status message and check the server's available capabilities. Do not assume every deployment has every build or execution feature.

### 6.9 Approvals, budgets and safety

Project mode intentionally separates suggestions from approvals. Read what an approval is for before acting. A budget approval may ask you to enter a new numeric limit; enter only a limit you understand and are willing to authorise. Reject or cancel if you are unsure. Do not approve a task or budget just because the button is available.

### 6.10 Google Drive and sign-out

- Use the Google Drive control to connect if it is configured for this server. A Google sign-in window may open.
- Project files are saved to Drive only when you use an explicit save action. The application does not silently publish a project to GitHub or deploy it for you.
- The connection may be available only while this browser tab is open. Read the status message in the workspace.
- Choose **More → Sign out** when finished on a shared computer.

### 6.11 Delete a project

In the project list, open the **⋯** menu next to a project and choose **Delete project**. Read the confirmation carefully. Deleting a project and its data cannot be undone. If you may need it later, export or save the relevant files first.

## 7. Files and attachments {#files}

### 7.1 Attach files to a conversation

1.  Use **Attach files** near the message box, or open the available file/workspace control.
2.  Select the files you want the assistant to consider. On supported desktop browsers, you may also be able to import a whole project folder through **More → Import → Project folder (desktop)**.
3.  For a project archive, attach one ZIP at a time. BiForge may unpack it into a local workspace.
4.  Check the file list and remove anything irrelevant or sensitive.
5.  In the workspace privacy panel, read the notice. Until you choose **I understand — let the assistant read these files**, the workspace is not included in the model context.
6.  After confirming, tell the assistant exactly what to do with the files, such as “Summarise the README” or “Find the configuration that controls the login page.”

Readable text from selected files may be sent to the AI provider when you use the assistant. Other files may be retained locally and described by name/type rather than read as text. Never include passwords, API keys, private keys, payment-card details, identity documents, or other information you would not want processed by the model.

### 7.2 Export a workspace

- **Download all (.zip)** downloads the files in the current workspace.
- **Changes only** downloads files that differ from the previous workspace version and a change list. It becomes available after a later version exists.
- **Text diff** downloads a readable text comparison with the previous version, when available.
- Store downloads in a known folder and use clear filenames so you can find them later.

### 7.3 Google Drive

Drive features are optional and depend on server configuration and your Google access. Use the Drive button or an explicit **Save to Google Drive** action. Read the status message to see whether a save succeeded. A cloud icon is not a guarantee that every local file has been uploaded.

## 8. Top bar, history, import and export {#topbar}

### Mode

Shows the current mode and opens the mode menu. Choose Simple chat, Expert method, or Project workspace if available. **Back to mode selection** returns to the mode chooser. When leaving Project mode, your projects remain on the server, but confirm before leaving if you have unsaved browser input.

### New

Starts a new conversation/decision dialogue. It does not mean “delete everything.” Use History or export to return to older work.

### History

Opens dialogues saved on this device. Select an item to reopen it. If History is disabled, the installation or current browser state does not provide it. History on this device is not the same as a server-wide account history; do not assume it appears on another device.

### More → Export all

- **Backup (.json)** — a machine-readable backup. Use this format when you want to import BiForge data again.
- **Readable text (.md)** — a text/Markdown copy that is easy to read or edit.
- **Word** — a document for editing or sharing in a word processor.
- **PDF** — a fixed-layout document for reading or sharing.
- **Google Docs** — sends an export to Google Docs when that integration is configured.

Choose a format, then follow the browser's download or save prompt. Keep backup files somewhere safe. An export is a copy; it does not automatically synchronise every future edit.

### More → Import

- **From backup (.json)** — select a BiForge backup JSON file. Review any import/merge information before relying on the result.
- **Project folder (desktop)** — available only in supported desktop browsers. It loads a folder into the local workspace; it does not deploy the project.
- **From Google Drive** — available when the Drive integration is provided. Select or connect the appropriate Drive source and check the status message.
- **From a file as a new dialogue** — imports a supported text, Word, or PDF document as a new dialogue context. The assistant can still misunderstand the document, so verify important details.

### Saved texts on this device

Opens texts saved from chats on this device. This is useful for retrieving a piece of generated text without searching through a whole conversation.

### Your Gemini API key

This optional setting may let you use your own Gemini API key if the installation supports it. Only use it if you understand the provider account and billing implications. Never paste API keys into ordinary chat messages. If you do not need this feature, leave it alone.

### New tab and Close in this guide

**New tab** opens a separate copy of this guide so you can keep it beside BiForge. **Close** returns you to your work. You can reopen this guide any time through **More → User guide**.

## 9. Privacy and safe use {#privacy}

- **Do not enter secrets.** Avoid passwords, API keys, private keys, payment-card numbers, identity documents, and confidential information unless you have checked the applicable data-handling rules and explicitly intend to share it.
- **Review file access.** The workspace asks for permission before its readable contents are made available to the assistant. Only grant it when you are comfortable sharing those contents with the AI provider.
- **Verify important claims.** Check legal, medical, financial, security, employment, and other high-impact information against reliable sources or qualified professionals.
- **Check generated code.** A source ZIP is not proof that software is secure, correct, or ready for production. Test it, review dependencies and configuration, and protect real user data.
- **Review before approving.** In Expert and Project modes, a suggestion, plan, task result, or generated file is not automatically correct or approved.
- **Publishing is manual.** BiForge does not automatically push your code to GitHub or deploy it to a hosting service. Follow the instructions and perform those actions yourself.
- **Understand where things are stored.** Simple/Expert conversations and workspace files may be stored locally in your browser; Project data is stored on the server. Drive actions depend on configuration. Export important work if you need a separate copy.
- **Shared devices.** Sign out of Project mode and avoid leaving sensitive files or conversations open where others can access them.

## 10. Troubleshooting {#troubleshooting}

| What you see                                 | What to try                                                                                                                                                                             |
|----------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Project is unavailable**                   | The server may have Project mode disabled, or your account may not be authorised. Ask the BiForge administrator. Simple and Expert may still work.                                      |
| **Sign-in fails**                            | Check that you are using the application password supplied by the administrator. Do not send it in chat. If it still fails, contact the administrator.                                  |
| **Run analysis is disabled**                 | Confirm the project description first, then enter a non-empty analysis task.                                                                                                            |
| **Confirm/Reject buttons are missing**       | They appear only for items that are still proposed. Already reviewed items may not offer the same actions.                                                                              |
| **A task cannot start**                      | Check its status and any displayed blocked reason. The plan may need approval, a required capability may be unavailable, or a limit may have been reached.                              |
| **Task completed but I am unsure it worked** | Inspect the actual output and acceptance criteria. Do not mark it passed until you can enter concrete evidence.                                                                         |
| **No source ZIP appears**                    | Read the build status and note. Code generation may be disabled or unavailable in this deployment, or the request may not have produced a package.                                      |
| **Drive is not connected**                   | Check whether Drive is configured for this server, allow the sign-in window if expected, and try the explicit Connect/Save action again. Read the resulting status message.             |
| **Import or export does not work**           | Check the file type, browser download permissions, available storage, and any error message. Use JSON for a BiForge backup that you plan to re-import.                                  |
| **Save rejected or data changed**            | The project may have changed in another tab or window. Reload the project and review the latest values before trying again.                                                             |

| **The page seems stuck**                     | Wait briefly, check your connection, and read any error/status message. If you reload, be aware that unsaved text in the current form may be lost.                                      |

## 11. Small glossary {#glossary}

AI assistant / model  
The software that reads your request and generates a response. It can be useful but can also be wrong.

Prompt  
The instruction or question you send to the assistant.

Context  
The information available to the assistant for the current task, such as your message and files you have allowed it to read.

Assumption  
Something treated as true for the purpose of an answer even though it has not been confirmed.

Requirement  
Something the project must do or a condition it must satisfy.

Artifact  
A saved file or output produced during project work.

Plan  
A proposed sequence of tasks. In Project mode it requires human approval before tasks can run.

Task validation  
A human check of whether the task output meets its acceptance criteria.

Source ZIP  
A downloadable archive of source files. It is not a live or deployed application.

Deploy / publish  
Make a software application available on a hosting service or to real users. This is a separate step from generating a ZIP.

## 12. Your first project: build Lab Escape {#lab-escape}

You are going to try a real project from beginning to end: a small browser escape-room game called **Lab Escape: The Last Keycard**. The goal is to learn how to describe an idea, review what BiForge understood, request a build, test the result, and improve it. You do not need to know how to code.

<div class="callout">

**A realistic promise:** this is a deliberately small project, not a guarantee that every BiForge installation can generate a working game in one click. Project Mode features depend on the server configuration and generated code can contain mistakes. If a step or button is unavailable, follow the capability notes in Section 6 and ask the administrator which project-building features are enabled.

</div>

### 12.1 What you are going to build

You are trapped in a small science laboratory. To escape, you must discover a clue, enter a code into an electrical panel, restore power, obtain an access card from a terminal, and unlock the exit.

The first version should contain:

- One screen showing a single laboratory room.
- Four clickable objects: a desk, an electrical panel, a terminal, and an exit door.
- A simple puzzle whose clue is found at the desk.
- A small inventory or status area showing what you have discovered.
- Clear messages explaining what happens after each action.
- A victory screen when the exit is unlocked.
- A **Restart** button so you can play again.

To keep the first attempt manageable, do **not** add accounts, online scores, a database, multiplayer, paid services, external APIs, or complicated animation. You can add extras after the basic game works.

### 12.2 Open Project Mode

1. Choose **Project workspace** from the **Mode** menu.
2. If BiForge asks you to sign in, use the application password supplied by the administrator. Never paste that password into the AI chat.
3. If the project-building choices appear, choose **Simple words**. It is designed for describing an idea without technical language.
4. If Project Mode or Simple words is not available, do not try to bypass the restriction. Use the available mode or ask the administrator whether project creation and ZIP generation are enabled.

### 12.3 Describe the game in your own words

In the **What do you want to build?** field, enter the following request. You can copy and paste it as written:

<div class="example">

Build a small browser game called “Lab Escape: The Last Keycard”. The player is locked in a science laboratory and must escape by solving one simple puzzle. Make a single-screen escape-room game with four clickable objects: a desk, an electrical panel, a terminal, and an exit door. The desk reveals a clue. The player uses the clue to enter a code into the electrical panel and restore power. The powered terminal provides an access card. The player can use the access card to unlock the exit and win. Show clear messages after every action, show collected items or progress, include a Restart button, and display a victory message when the puzzle is complete. Use a simple, attractive science-lab theme that works on desktop and mobile screens. Keep the game small and easy to understand. Do not add accounts, a database, online features, paid services, external APIs, or unnecessary dependencies. The game should run locally if the generated package supports that. Include clear instructions for running and testing it.

</div>

This is a **prompt**: a written instruction for the AI. It describes the goal, the main interactions, and what to leave out. You do not need to know the technical details to ask for a useful result.

### 12.4 Choose the product type and answer the setup questions

1. Choose the closest product type offered by BiForge, such as a small web application or browser-based tool. The exact choices may vary by installation.
2. If asked whether users need to sign in, choose **No** for this game.
3. If asked whether the project needs a database, choose **No**.
4. Choose **English** for the interface, unless you want to practise another language.
5. If asked about technical setup, choose **Choose for me** if you are unsure.
6. Add or keep these constraints if the form offers them: **small first version**, **mobile-friendly**, **no external APIs**, **no paid services**, and **no user accounts**.
7. Continue to the project summary.

Do not worry if a label is slightly different. Read the available options and choose the closest match. If a question is unclear, ask BiForge to explain it before proceeding.

### 12.5 Review the project summary before creating anything

Read the summary slowly. Check these points:

- Is the project a small browser game, not a large online game?
- Does it include the desk clue, code panel, powered terminal, access card, and exit?
- Does the game have a clear win condition and a Restart button?
- Does it avoid accounts, a database, external APIs, and paid services?
- Does it include instructions for running and testing the result?

If something is wrong, go back and correct the description. You can also ask BiForge:

<div class="example">

Please revise the project summary so it matches my original request. Keep the first version small. Do not add features I did not ask for. List any requirement you cannot support or are uncertain about.

</div>

When the summary matches your idea, choose **Create project &amp; build ZIP** if that action is available. Wait for the operation to finish and read the status message. Do not assume the build succeeded just because you clicked the button.

### 12.6 If you use the Professional path instead

If you chose **Professional**, create a project with a recognisable name such as **Lab Escape — The Last Keycard** and set its goal to **Create a small, locally runnable browser escape-room game for beginners**. Save and confirm the project description before running analysis.

For the analysis task, you can use:

<div class="example">

Review the requirements for Lab Escape: The Last Keycard. Identify missing requirements, likely implementation risks, and a small first-version plan. Keep the game to one room, four clickable objects, one code puzzle, an inventory/status area, a victory state, and a Restart button. Do not add accounts, a database, online features, external APIs, or paid services. Separate confirmed requirements from assumptions and tell me if any requested capability may not be available.

</div>

Read the results and confirm only suggestions that are accurate. Reject suggestions that change the game into something larger or different. Then create a simple plan if that option is available. Review every task and approval before starting it. If a task asks you to approve an action you do not understand, stop and ask for an explanation.

### 12.7 Download and inspect the result

If BiForge provides **Download source ZIP**, download it to a folder you can find again, such as **Downloads/Lab-Escape**. A ZIP is a package of source files; it is not automatically a published website.

1. Open the downloaded ZIP in your computer's file manager.
2. Extract it to a new folder. Do not edit files while they are still inside the ZIP.
3. Look for a `README` or other run instructions. Read them before opening or running anything.
4. If the package is a simple static web game and includes an `index.html`, the instructions may tell you to open that file in a browser. If it includes `package.json`, a build folder, or other setup files, follow the package's instructions instead; it may require a local development server or installed tools.
5. If you are unsure, return to BiForge and ask it to explain the exact files it generated and the safest way to run the game on your computer. Do not run unknown scripts with administrator privileges.

If no ZIP is offered, read the displayed status and the **Code package** or **Create a program** notes in Section 6. This may mean code generation is not enabled for this BiForge installation. Do not claim the game has been built until you can inspect an actual output.

### 12.8 Play-test the game like a detective

Try the game from a fresh start. Use this checklist and record what happens:

1. **The desk:** clicking it reveals a clue or code hint.
2. **Wrong code:** entering an incorrect code does not restore power.
3. **Correct code:** entering the correct code restores power and changes the game's status.
