# Архив: раздел 0.4 и Приложение C (трассировка v1.4 → v2.0 → v3.0)

### 0.4. Что изменилось относительно v2.0

1. **Jules и Mistral выведены из MVP** и перенесены в Приложение F вместе с допущениями, ADR, шагами и инструкциями подключения. Основание — практическая проверка владельца (дата и результаты — F.0).
2. **Появился интерфейс CodeExecutor** (п. 11.4). Раньше он был размазан по тексту как «режимы M и A Jules».
3. **Провайдеры моделей определяются реестром**, а не ТЗ. Адаптеры выбираются по формату API (`gemini`, `openai-compatible`, `anthropic`, `fake`).
4. **План перестроен вертикальным срезом** (D-15, разделы 16–17): новый шлюз G1a, раздел 18.0.
5. **Крупные шаги разбиты**: BX-03, BX-10, BX-12, BX-13, BX-15, BX-17, BX-18, BX-21, BX-22. Перед разрезанием монолитов (BX-03) требуются характеризационные тесты.
6. **Базовая линия** обязана быть зелёной до начала работ (BX-01.a); документы приводятся в порядок (BX-01.b).
7. **Контракты сущностей определяются вместе с шагом, которому они нужны** (BX-05 сужен). Список таблиц в п. 5.2 — ориентир, а не обязательство.
8. **Golden-eval (BX-14) — гипотеза, а не решение.** `cross_model` включается политикой, эффект наблюдается по ledger.
9. **Облегчённый процесс** для шагов без отметки ★ (п. 16.3).
10. Добавлены **stop-правила для агента разработки** (п. 16.3): ограничение времени до первого опубликованного результата и критерии остановки при зацикливании. Основание — журнал сессии Jules (F.0).
11. Добавлен **эксперимент E-01** (п. 11.9) вместо допущения о Jules API: проверка того, что модель по API выдаёт применимый патч.
