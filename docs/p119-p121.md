## Патчи до конца проекта 

Сейчас сделаны P119.0.1–0.3. Остаётся хвост P119 из четырёх патчей, затем P120 и необязательный P121. Между патчами нужны решения Навигатора. Источник последовательности — `ROADMAP.md`, фазы 6 и 7.

### Сначала (до P119.0.4)
- Подтвердить зелёный CI на P119.0.1, P119.0.2 и P119.0.3. Навигатор ПОДТВЕРДИЛ CI - зеленый. Заодно гоняется `ui-check`.
- Принято решение: идти на P119.0.4.

### P119 — завершение трёх агентов

**P119.0.4 — следующий шаг изоляции.** До начала предложить Навигатору оптимальные решения.
- Вынести тексты промптов Conversational и Expert из общего `promptPacks.ts` в файлы самих агентов. Побайтную идентичность сохраняю, чтобы не ломать принятое поведение.
- Решить, нужны ли агентам отдельные имена маршрутов. Сейчас общий `POST /api/conversation` и поле `productMode`. Переименование ломает совместимость со старыми клиентами, поэтому предложить решение для наилучшего результата проекта и наилучшего пользовательского интерфейса.
- Удалить импорт старого IR-конвейера из `server.ts`, но только если ни один деплой не запускается с `engine=legacy`. Предложить Навигатору оптимальное решение.
- Проверки: полный CI, обновление тестов `KNOWN_SHARED_PATH` в том же патче.

**P119.0.5 — workflow только там, где CI не покрывает.** Здесь не плодим дубли: `ci.yml` уже гоняет контрактные тесты, `ui-check.yml` проверяет меню агентов. Реально не покрыто одно: ручной живой smoke, что каждый из трёх агентов запускается и отвечает честно на задеплоенном коммите. Это `p119-agent-contracts` и `p119-ui-smoke`. Запуск требует секретов стенда.

**P119.0.6 — остатки legacy и регрессия Architect.**
- Решить, считать ли вкладку «Advanced» (сырые данные проекта) четвёртым режимом. Решение Навигатора четвёртого режима нет, только простой диалоговый, экспертный и проектно-архитектурный.
- Регрессия Architect: сборка, валидаторы, скачивание ZIP. Workflow `p119-regression` на основе `p118-architect-live`.

**P119.0.7 — Release Gate P119.** Полный CI, `test:ui` и живые сценарии для всех трёх агентов, результаты привязаны к коммиту. Затем решение Навигатора: закрываем P119 или нет. Правило остановки: любая регрессия принятого поведения P116/P117 останавливает работу и возвращает вопрос вам.

### P120 — сквозная проверка и приёмка
Начинается только после вашего решения по P119.

| Патч | Что делает |
|---|---|
| P120.0.1 | E2E Conversational: полный пользовательский сценарий |
| P120.0.2 | E2E Expert: сценарии и пути ошибок |
| P120.0.3 | E2E Architect: сборка, валидаторы, скачивание, целостность ZIP |
| P120.0.4 | Переходы между агентами и сохранение контекста |
| P120.0.5 | Стабилизация, исправление найденных регрессий |
| P120.0.6 | Workflow `p120-acceptance` и `p120-evidence`, единый отчёт доказательств |
| P120.0.7 | Финальная приёмка и документы закрытия |
| P120.0.8 (по условию) | Остатки P118: политика скачивания при `PARTIAL`, аудит зависимостей `zod`, `body-parser`, `qs` |

Условие закрытия P120: обязательные E2E проходят, ложного `SUCCESS` нет, результаты привязаны к проверенному коммиту. P120.0.8 включаем, только если инвентаризация подтвердит, что эти хвосты ещё актуальны и мешают релизу. Финальная приёмка —  решение Навигатора (Tier 3).

### После P120
Проект по программе закрыт. P121 (слой устойчивости к моделям, доступ через браузер) по решению Навигатора. Он стартует только после явного «да» и закрытия открытых решений. Это отдельный большой объём: квоты, приватность, стоимость требуют политики. Озвучить янавигатору оптимальные рекомендации Ассистента.
