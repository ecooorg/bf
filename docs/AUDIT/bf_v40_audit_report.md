# BiForge v40 — независимый статический аудит архива

**Объект:** `bf-v40.zip` (снимок исходников, без запущенной среды). **Тип:** инвентаризация всех файлов, построчный машинный просмотр исходного кода и предварительная трассировка требований. **Не является:** подтверждённым полным семантическим построчным code review или результатом исполнения CI.

## Охват и метод

- Проинвентаризированы **407 файлов** с SHA-256, включая **133 Markdown-документа**.
- Из **49 документов**, выбранных по именам `*SPEC*`, `*TZ*`, `MASTER_IMPLEMENTATION_PLAN.md` и др., выделены **764 строки-кандидата на требования** (пункты списков, нумерованные требования и некоторые строки таблиц). Это **не гарантия охвата всех требований**: абзацы, ADR, чек-листы и требования в иных документах могут не попасть в извлечение.
- Построчно программно просмотрены **23 258 строк 128 файлов JS/TS/TSX/MJS**, выполнен поиск маркеров риска; выделены **12 совпадений**. Большинство совпадений — обычные вызовы `.exec()` у регулярных выражений; это не уязвимости.
- Найден **91 файл тестов**; матрица содержит кандидатов на соответствующие строки кода/тестов. **Связи эвристические (совпадение слов), а не доказательства реализации.**
- Для **174** строк требований не удалось найти достаточно похожий фрагмент кода, для **87** — достаточно похожий тест. Эти числа **не означают 174 отсутствующие функции и 87 отсутствующих тестов**: возможны ложные отрицания и ложные соответствия.
- **Не выполнялись** `npm ci`, `npm run check`, `npm run build`, браузерные, provider/live и staging-проверки. Сообщение владельца «CI зелёный» не заменяет артефакты конкретного запуска.

## Как читать матрицу

`bf_v40_requirements_matrix.csv` — **предварительный реестр**, а не аттестация PASS. Для каждого пункта: оригинальная строка ТЗ, файл и строка, до двух кандидатов кода и тестов, статус доказательности и риск. Обозначение `lex=N` — число совпавших содержательных токенов. Для реального закрытия нужно вручную проверить смысл требования, пройти вызовы и ветвления, установить тестовые assertions и зафиксировать фактический результат.

`bf_v40_file_inventory.csv` — полный список файлов архива, число строк и SHA-256. `bf_v40_code_flags.csv` — все совпадения простого статического сканера; **не** список доказанных дефектов.

## Итог

**Нельзя обоснованно объявить «весь код точно закончен» на основании этого статического анализа.** Прямого доказательства новой обязательной функции, которую нужно дописать сейчас, не найдено. Но полная приёмка ещё не завершена, а обязательный QA1 следует подтвердить именно как интеграционное выполнение, не только проверку исходного текста. Для окончательного вердикта необходимы запуск тестов в воспроизводимой среде, сверка каждого критерия с утверждениями тестов, трассировка runtime-путей и ручная приёмка владельца.
