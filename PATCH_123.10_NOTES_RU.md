# Патч BiForge 123.10 — глубокий ремонт качества информации и Architect

## Что исправлено

### Поиск и Simple
- Добавлено контекстное разрешение коротких follow-up запросов. В частности, вопрос о градусах Цельсия после запроса погоды теперь передаёт в поиск город из последних пользовательских реплик.
- Контекст берётся только из последних пользовательских сообщений и используется только для разрешения явного продолжения; полноценный самостоятельный запрос не переписывается.
- Добавлен регрессионный тест на сценарий «погода в Цюрихе» → «интересует погода в градусах Цельсия», а также тесты против загрязнения независимого запроса.

### Проверка чисел
- ISO-даты больше не разбиваются на отдельные неподтверждённые числа.
- Добавлена арифметическая проверка пар Fahrenheit/Celsius: корректная конвертация и её стандартные константы не запускают ложный retry; ошибочная конвертация остаётся ошибкой.

### Expert
- Устранено противоречие между требованием отвечать прямо на фактические вопросы и требованием всегда сохранять полный аналитический разбор.
- Явно задано соразмерное глубине задачи поведение: короткий фактический ответ не превращается в decision workshop.
- Уточнено право давать рекомендацию: эксперт не принимает решение за пользователя по умолчанию, но если пользователь прямо просит рекомендацию, она должна быть условной, привязанной к его критериям и объяснять решающий компромисс.

### Architect
- JS-валидатор теперь разбирает JavaScript как ES-модуль, а не как classic script. Ранее `vm.Script` отвергал корректные `import`/`export` конструкции.
- Добавлена отдельная проверка локальных модульных контрактов: существование импортируемых файлов и наличие named/default exports.
- Новый валидатор включён в обязательный список приёмки.
- Переписаны инструкции planner/coder/reviewer: план должен заранее фиксировать карту файлов, модульную систему, экспортируемые API и схемы данных; reviewer обязан проверять целостность приложения как связанной системы.
- Версии prompt/cache подняты, чтобы старые результаты не переиспользовались после изменения инструкций.
- Усилен запрет на фиктивные fallback-значения: сбой источника должен давать unavailable/null, а не правдоподобную выдумку.

### Диагностика
- `WARN`/`PARTIAL` исход последней сборки больше не теряется среди зелёных инфраструктурных проверок.
- В диагностический контекст добавлены latestBuild и artifactOutcome; итоговый статус учитывает не только здоровье инфраструктуры, но и исход последней сборки.
- Неуспешные и частичные исходы попадают в список последних проблем.

### Общий workflow качества
- Добавлен исполняемый `scripts/information-quality-eval.mjs` с JSON/JSONL-входом, проверками происхождения источников, hard gates, агрегированием оценок и ненулевым exit code при провале. Он подключён к `npm run test:information-quality` и общему `npm test`.
- Добавлен `docs/INFORMATION_QUALITY_WORKFLOW.md`: сценарии для Simple, Expert и Architect, 7-мерная шкала оценки, жёсткие блокирующие критерии, протокол одинаковых evidence-пакетов, слепая проверка и pre-release workflow.

## Важные замечания
- Экспертный режим в текущих тестах показывает более содержательный ответ, но тестовая выборка слишком мала, чтобы объявлять его доказанно лучшим. Требуется прогон одинаковых сценариев и многоходовых диалогов.
- Изменения в Architect предотвращают обнаруженные ошибки модульного связывания на статическом уровне. Полная runtime-приёмка с mock API и браузером по-прежнему обязательна; статический контракт сам по себе не доказывает, что приложение корректно работает.
- Полный `npm test`, typecheck и browser E2E в этой среде не запускались: зависимости проекта не установлены. Изменённые TypeScript-файлы прошли синтаксическую транспиляционную проверку TypeScript 5.8.3 без синтаксических диагностик. Это не эквивалент полного typecheck или исполнения тестов.
