# C124 Instruction and Output-Transformation Inventory

**Audit stage:** P124.1 — source inventory  
**Repository patch identity at inventory creation:** `124.0.3`; P124.2 dispositions are recorded below  
**Audit status:** STATIC_SOURCE_INVENTORY_COMPLETE; runtime/model-backed behavior NOT_RUN  
**Scope:** production source under `server/`, `appBuilder/`, and the model-facing integration paths.  
**Method:** source search, import/call-path tracing, inspection of prompt assembly and post-processing, and cross-check against current tests. Line references are valid for the P124.0.2 source baseline and are guarded by `tests/c124-instruction-inventory.test.mjs`.

## 1. Executive findings

The inventory confirms that BiForge currently contains several layers of substantive reasoning instructions in addition to the external model's own capabilities. The most consequential duplication is:

1. At inventory time, `server/promptPacks.ts` embedded a long decision-analysis method with mandatory stages and response expectations. P124.2 replaced it with concise task-fit guidance.
2. At inventory time, `server/reasoningState.ts` added the V17 prompt layer. P124.2 removed that model-facing prompt while retaining deterministic state utilities.
3. At inventory time, `server.ts` defined a separate analytical-engine `BASE_SYSTEM`. P124.2 replaced it with a concise task/schema/evidence/safety interface contract.
4. At inventory time, `server/expertAgent.ts` added a fixed Expert analysis recipe. P124.2 rewrote the dialogue framing and step prefix; the UI stage and session context remain available as data.

These were not merely transport or formatting controls. Several prescribed how the model must think, what novelty each reply must contain, and how to structure decisions. P124.2 removed the mandatory dialogue reasoning choreography and novelty-only retry while retaining safety, honesty, evidence, user-agency and output-schema requirements. The remaining staged endpoint prompts are not included in that cleanup.

Other prompt groups are legitimate model-communication contracts: web-search tool use, JSON schemas, file-generation markers, Architect state-patch schema, and the optional claim-classifier task. These should not be removed merely because they are prompts. Their scope and overlap should be minimized and mechanically enforced where possible.

A separate risk exists after the model call: BiForge applies several transformations that can remove URLs, Markdown structure, questions, labels, document text, attachment notes, state entries, and context. Some are intended safety/format controls; others may silently discard useful model output. These transformations are included in this audit because the user-visible answer is not always the raw model response.

## 5. Hard-coded and phrase-triggered behavior

The audit found deterministic phrase lists in `server/conversationMode.ts:L9-L30` and `server/webSearch.ts:L69-L115`, plus specialized rate-topic detection and seed URLs in `server/webSearch.ts:L149-L165`. These are not prompt text; they are code-level heuristics that choose a route or retrieval strategy. They are not automatically wrong: routing, privacy and cost controls are engineering functions. They are nevertheless special cases and need false-positive/false-negative evidence, especially for multilingual and elliptical messages.

P124.0.2 already removed one explicit weather-city allowlist and one Zurich example. The remaining inventory does not claim that every phrase trigger, provider seed URL, or topic expansion has been justified. Rate-topic handling and the weather follow-up parser remain under review.
