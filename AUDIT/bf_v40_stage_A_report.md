## Обнаруженная методологическая проблема предыдущей матрицы

В матрицу попали пункты типа `Out of scope` (например R0001), описания и исторические ограничения. Их нельзя помечать как невыполненные задачи. Связи с кодом/тестами — лексические кандидаты, а не семантические доказательства. Не следует превращать 174/87 в баг-репорт. Для строгого закрытия нужно сначала нормализовать требования (действует / историческое / отменено / out-of-scope / решение владельца), затем для каждого действующего обязательства проверить реальные ветки и assertions.

## Дополнительное наблюдение о UI

`tests/ui-check.mjs` использует fallback на старый экран `Start`, если карточка Simple не найдена; это снижает строгость проверки UI1. Если старый экран сохраняется, тест может продолжить выполнение вместо немедленного FAIL. Хотя позднее проверяются другие элементы, наличие fallback означает, что UI1 не доказан строго этим тестом. Это **подтверждённая слабость тестового оракула**, а не подтверждённый дефект интерфейса.

## Что НЕ обнаружено

При выполненных проверках **нет доказанной отсутствующей обязательной функции или критического дефекта runtime-кода**. Это не равнозначно доказательству отсутствия таковых. Поскольку полная семантическая трассировка всех действующих ТЗ и интеграционные прогоны не выполнены, окончательный PASS этапу A ставить нельзя.

## Решение по этапу A

**Статус: PARTIAL / требуется дополнительная доказательная проверка.** Подтверждены документальные/тестовые пробелы A-01…A-06, один тестовый риск UI и открытые owner-gates. **Не начинать программирование** без отдельно подтверждённого дефекта и команды владельца. Для завершения этапа A нужны: нормализация реестра ТЗ, трассировка runtime по каждому действующему требованию, отчёты CI+UI для того же SHA, затем тесты с воспроизводимым окружением.
