# P13b — SPEC: устойчивый процесс сборки и доставка частичного патча

## Цель
Сделать сборку патча конечной по времени и не терять архив из-за красных проверок, сохранив блокирующий preflight безопасности.

## Критерии приёмки
- Каждая команда имеет таймаут, принудительно завершается вместе с группой процессов и пишет потоковый лог в `patch-logs/<PNN>/<key>.log`.
- После успешного preflight архив строится и проверяется до длительных проверок; красные проверки отражаются как `PARTIAL` с таблицей этапов и путями к логам. ZIP повторно читается, проверяются количество файлов и содержимое.
- `--steps` позволяет запускать независимые npm scripts, чтобы падение одного теста не скрывало результаты остальных. `check` разбирается на независимые скрипты; `build` запускается ровно один раз.
- Команды `node --test` имеют таймаут теста и принудительный выход; живые тесты БД последовательны.
- PostgreSQL ограничивает время SQL statement, ожидания блокировок и idle-транзакций.
- NEXT.md и AGENTS.md описывают лимит двух попыток починки, `KNOWN_FAIL`, `TIMEOUT` и честную маркировку `PARTIAL`. Любой `NOT_RUN`/`BLOCKED` не считается PASS; PARTIAL не разрешает автоматическое развёртывание.

## Ограничения
Preflight по секретам, манифестам, защищённым путям и структуре архива остаётся блокирующим. Этот патч не утверждает, что продуктовые проверки зелёные, и не запускает P13b функциональную реализацию воркера.
